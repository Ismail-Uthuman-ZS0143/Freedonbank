Intake as a role-based workflow

The intake stage segregated into five accountable roles. Four are workspace roles with their own screens and queues; the applicant participates by secure email alone — no login, no application access. Every document still ends in the same place: verified, twinned, and committed to the Credit File Server.

1 · Intake OwnerAPPLICANT→ 2 · CoordinatorINITIATE & VALIDATE→ 3 · ReviewerOWN PACKAGE · ASSIGN→ 4 · CheckerMISSING & INVALID→ 5 · ApproverCOMMIT TO SERVER

⟲ Re-request loop: the Checker sends findings straight to the Owner as a secure re-request; the Coordinator tracks completeness — missing or invalid documents never move forward silently.

ROLE 5 · INTAKE APPROVER

Commit the package to the Credit File Server

R. Douglas · Intake approver
In: clean packageOut: twinned documents → extraction

The gate out of intake — and the stage’s overseer: the Approver lands on the intake operations dashboard, watching every application, queue, and SLA across all roles. Confirms every Checker finding is resolved, then commits the parking-bay package into the Credit File Server — the moment each document becomes a twin and the extraction pipeline takes over. Separation of duties by design: the Approver assigned none of the checks and made none of the findings.
